## 五、已修与未修

### 已修（本轮）

**① `utils/state.js` 加内存缓存** — 这是真实存在的性能浪费

原来每个 `has()` 都调一次 `wx.getStorageSync`，而列表渲染是逐条判断的：
`items` 页一次 `syncMine()` 要读 **10 次 Storage**，`onShow` 又频繁触发。
改成进程内缓存后，读取走内存，写时同步更新内存与 Storage。

**② 修正体检脚本两条误报规则**

- 定时器检查原来只认 `_alive` 存活标记，不认 `onUnload` 里的 `clearTimeout` → `index.js`、`search.js` 写对了却被报成隐患。已加豁免。
- "是否在循环里 setData"这条规则被**删除**。正则无法判断循环作用域，会把循环之后的语句也算进去（`post-detail`、`diagnose` 就是这么误报的）。改为只统计次数，由人判断——批量渲染时一次 `setData` 传整个列表是正确做法，逐条 `setData` 才需要改。

### 未修（有意保留）

| 项 | 为什么不改 |
|---|---|
| `app.wxss` 40.8 KB | 小程序编译后会把 wxss 合并，拆文件不减少最终体积，只增加维护成本 |
| `mock.js` 28 KB | 原型阶段必需，接真实接口后整个文件移除 |
| PNG 35.7 KB | tabbar 图标已是最小可用尺寸，再压会糊 |
| items 页深度 7 | 元素总数只有 92，实测无压力 |

## 七、建议清单

**提审前（必做）**
1. 删除 `pages/diagnose/` 整个目录，并从 `app.json` 的 pages 数组移除
2. 删除 `pages/activities/` 和 `pages/tasks/`（内容已并入 `items`，属死页面）

**可选（10 分钟）**
3. 精简 `icons.wxss`：当前 28 个图标，实际只用到约 16 个
   用法：把 `gen-icons-png.py` 的 ICONS 字典裁到实际用到的，重跑脚本

**不建议**
4. 拆 wxss / 压图片 / 重排页面结构 —— 收益低于改坏的风险
