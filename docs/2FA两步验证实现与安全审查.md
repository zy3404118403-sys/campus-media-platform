# 2FA 两步验证实现与安全审查记录（2026-08-31）

## 一、功能概述

为校融媒体平台实现 TOTP 两步验证（RFC 6238），零依赖（node:crypto），覆盖**绑定 → 验证 → 备用恢复 → 关闭保护**全环节，与现有登录流程完全兼容（未启用者一步登录不变）。

**入口**：个人中心（/user.html）→ 账号设置 → 两步验证卡片。任何登录用户可为自己的账号开启，推荐管理员开启。

## 三、登录流程（兼容性设计）

```
第一步 POST /api/login（不变）
  ├─ 未启用 2FA → 照旧直接发会话 cookie（现有用户零感知）
  └─ 已启用 2FA → 不发会话，返回 {need2fa:true, challenge:64位随机}
第二步 POST /api/login/2fa {challenge, code}
  ├─ code 为 6 位数字 → TOTP 校验（±1 步容忍时钟漂移）
  └─ code 为 10 位字母数字 → 备用恢复码（哈希比对，用后即焚）
  通过 → 照旧发会话 cookie；失败 → 计入 IP 限速，挑战最多 5 次
```

挑战特性：随机 64 hex、绑定 userId、5 分钟过期、一次性、进程重启即失效（fail-closed，用户重新走第一步）。

## 四、关键安全设计

1. **密钥不出服务器**：`/api/me` 与一切公开接口只返回 `totp_enabled` 布尔值；明文密钥仅在绑定阶段（未启用时）返回一次，启用后任何接口不返回
2. **备用码只存哈希**：SHA-256 存储，明文仅在生成时显示一次；输入大小写不敏感、去横线
3. **关闭需要双因素**：密码错误 → 403（先验），动态码错误 → 401——密码泄露无法单独关闭 2FA
4. **防爆破**：第二步复用登录限速（5 次失败锁 15 分钟）+ 挑战 5 次尝试上限；TOTP 恒时比较
5. **CSRF 策略**：`/api/login/2fa` 免 CSRF（无会话状态，攻击者无法伪造他人挑战）+ 64 位随机挑战 5 分钟内单次有效，重放/伪造均不可行；其余 5 个 2FA 端点全部要求登录态 + CSRF 双提交头（本地测试 C3 验证缺头被 403）

## 五、验证结果

- **TOTP 单元测试 8/8**：RFC 6238 官方测试向量（59s → 287082）通过；编解码回环、±1 窗口、超窗拒绝、备用码格式/哈希/判定
- **API 端到端 29/29**（`test-2fa.cjs`）：兼容性 A1-A4、未登录 B1、绑定启用 C1-C8（含 CSRF 缺头拦截 C3、密钥不泄露 C8）、两步登录 D1-D7（挑战伪造/一次性/不下发 cookie）、备用码 E1-E4（小写兼容/一次性/剩余计数）、关闭保护 F1-F5
- **UI 全流程 12/12**（`ui-smoke-2fa.cjs`）：绑定面板 → 启用显示备用码 → 登出 → 两步登录 → 备用码登录 → UI 关闭，全程无 JS 错误
- **云端**：8 文件部署成功、自动重启正常、`/api/me/2fa` 未登录 401、伪造挑战被拒、静态版本 p2v4 到位。**云端未对真实账号启用 2FA**（遵守"云端账号勿动"约定），由你在管理账号上自行开启

| 4 | 登录/2FA Set-Cookie | 无 `Secure` 标志 | 站点尚未上 HTTPS（备案中） | HTTPS 前属预期；上线后必须补 | 🟡 已记入 HTTPS 上线清单：届时 nginx 443 + Cookie 加 `Secure` + OG 地址同步 |
