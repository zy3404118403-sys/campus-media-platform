# 小程序管理后台 · 设计说明

- 版本：v1（2026-11-03）
- 对应代码：`miniapp/pages/admin*`、`miniapp/utils/admin-ops.js`；后台样式在 `miniapp/app.wxss` 末尾
- 页面数：30（新增 7 个管理页；同时删掉 `pages/activities`、`pages/tasks` 两个无入口死页）

---

## 一、为什么不是把 Web 后台搬过来

Web 后台有 11 个模块（`admin.js` 的 `SM_ADMIN.getItems()`）：

| Web 模块 | 小程序是否保留 | 理由 |
|---|---|---|
| dashboard 总览 | ✅ 保留 | 手机上先看数再决定要不要处理，是所有操作的入口 |
| review 审核队列 | ✅ 保留 | **手机端最有价值的功能**：审核是碎片时间做的，等回电脑就压单 |
| materials 素材管理 | ✅ 保留（精简） | 只留下架/精选两个即时动作，编辑类操作留给电脑 |
| users 用户管理 | ✅ 保留（精简） | 只改角色与上传限制，不提供批量导入导出 |
| activities 活动管理 | ✅ 保留（发布 / 结束 / 报名情况） | 突发事件多（场地改、时间调），管理员常在手机上就要发通知式活动 |
| recruits 招新管理 | ➖ 不做 | 需要看简历附件与多轮状态流转 |
| audit 审计日志 | ➖ 不做 | 大表格，手机上一屏看不了几行 |
| access 访问统计 | ➖ 不做 | 图表型分析，电脑端体验明显更好 |
| mediaMatrix 媒体矩阵 | ➖ 不做 | 需多平台 OAuth 与图文排版 |
| articlesWorkbench 文章工作台 | ➖ 不做 | 长文编辑与富文本排版 |
| notifications 通知 | ✅ 保留 | 突发通知（如"今晚操场拍摄取消"）恰恰在手机上发 |
| tasks 任务管理 | ✅ 保留（发布 / 截止 / 领取情况） | 与活动同源，放在一起最省事 |

**判断标准只有一条**：这个操作在手机上「能不能在 3 分钟内做完」。
能做完的搬运过来，需要长时间读写的留在大屏。

## 二、角色模型

三级，写死在 `utils/auth.js`：

| 角色 | 取值 | 能做什么 |
|---|---|---|
| 管理员 | `admin` | 全部 5 个模块 |
| 审核员 | `reviewer` | 只能进审核队列 |
| 成员 | `member` | 看不到管理入口 |

为什么单独设「审核员」：内容组同学可以帮忙审素材，但不该能改成员角色、也不该能给全校发通知。
这类越权在真实运营里最容易出事。

**两条硬规则**（代码里写死，不是提示语）：

1. **管理员不能改自己的角色**（`admin-users.js` 的 `onMember`）
   —— 否则把自己降成成员后，再没人能进后台。
2. **含肖像风险的素材不能批量通过**（`admin-review.js` 的 `onPass`）
   —— 必须逐条弹窗确认「已取得同意」。

## 三、七个页面

### 1. 工作台 `pages/admin`

- 四个指标：待审核 / 素材总数 / 开通账号 / 已下架（全部从真实数据派生，不另存一份）
- 待办三条：待审素材、含肖像风险（需逐条确认）、被限制上传的成员
- 四个模块入口；审核员看不到的三个置灰并提示「仅管理员可用」

> 「开通账号 466」直接读 `pointOverview.totalUsers`，与贡献值页共用同一个数，
> 避免又出现一处"两套数字"。

### 2. 审核队列 `pages/admin-review`

- 类型筛选（全部/视频/图片/文档）
- **系统预检提示**：给审核员的参考信息（含可识别面孔、疑似版权音乐、帧率偏低等），
  明确标注「不代替人判断」
- 通过 → 素材**真的进入素材库**（`utils/admin-ops.js` 的 `approve`）
- 退回 → 必须从 6 条预置原因里选一条，与 Web 后台口径一致
- 批量通过只处理「系统预检无风险」的条目

### 3. 内容管理 `pages/admin-materials`

- 搜索 + 筛选（全部 / 已精选 / 已下架）
- 精选：打标
- 下架：**真的影响前台** —— 素材库与首页都不再显示，且写入本地存储，重启仍生效
- 下架是软删除，可恢复；彻底删除引导去 Web 后台

### 4. 成员管理 `pages/admin-users`

- 搜索 + 角色筛选
- 点某人 → ActionSheet 改角色 / 限制上传
- 降级管理员有二次确认

### 5. 事项管理 `pages/admin-items`（活动 / 任务）

- 顶部胶囊切换「活动 / 任务」，统计草稿 / 进行中 / 已结束
- 列表里**能看到草稿**（C 端看不到）
- 操作按状态给：草稿 → 「发布」；进行中 → 「结束 / 截止」；任何状态都可「编辑」
- **有报名的活动、被领取的任务不显示删除**，只能结束

### 6. 事项编辑 `pages/admin-item-edit`

- 一个页面承接两种对象，靠 `?kind=activity|task&id=` 区分
- **流程 / 须知 / 要求都用「一行一条」的多行文本**，提交时拆成数组——
  手机上反复点「添加一行」比直接换行麻烦得多
- 活动：名称、地点、显示时间（留空按截止时间自动生成）、截止、名额、贡献值、简介、流程、须知
- 任务：名称、成果类型（视频/照片/设计）、贡献值、名额、截止、描述、交付物、要求

### 7. 通知发布 `pages/admin-notice`

- 标题（40 字上限）+ 正文（200 字上限），实时字数
- **发送范围：左侧「全体成员」按钮 + 右侧可展开的「学院 / 部门」选择器**
- 发送前二次确认（**写明发送后无法撤回**）
- 下方是已发送记录，带已读比例

范围控件为什么不是一排胶囊：最初把「全体成员 + 6 个学院」共 7 个选项平铺成横向滚动胶囊，
一屏放不下、右侧被截断，而且「全体」和「具体学院」是两个层级，混在一排里看不出从属关系。
改成：

- 左边一个独立按钮「全体成员 · 466」，选中时金色高亮
- 右边一个选择器，未选时显示占位「选择学院 / 部门」，选中后显示学院名（超长省略）
- 点右侧展开成列表（含融媒体中心这个部门），每项带人数与单选圆点，选中后自动收起
- 展开指示用 **CSS 三角**旋转，不用 `▲/▼` 字符（字符在各机型的基线与粗细不一致）

## 四、活动与任务的状态机

```
活动   草稿 ──发布──▶ 可报名 ──结束──▶ 已结束
任务   草稿 ──发布──▶ 进行中 ──截止──▶ 已截止
```

跳级会被拒（`publishActivity` / `closeActivity` 里判断前置状态）：
草稿直接结束会让 C 端出现一条**从没开放过的「已结束」活动**。

两条防误删：

- 已有报名的活动不能删（`joined > 0`），只能结束
- 已被领取的任务不能删（`claimedCount > 0`），只能截止

**草稿不进 C 端**：`mock.publicActivities()` / `mock.publicTasks()` 过滤掉草稿，
事项页、首页、内容关系页都只读这两个函数，不直接读 `mock.activities`。

## 五、四条数据红线

1. **学号只存脱敏形式**
   `adminUsers` 里字段叫 `sidMask`（如 `2026****0033`），完整学号根本不进这份数据。
   页面没有任何「查看完整学号」的按钮 —— 从数据层就没有，不是靠前端隐藏。
   背景：Web 后台用户页曾整表露出 13 位真实学号（含本人），截图外流风险过高。

2. **草稿不能出现在前台**
   C 端取活动/任务一律走 `publicActivities()` / `publicTasks()`。
   脚本 [12] 会检查「前台可见集合里没有草稿」「草稿的报名数/领取数为 0」。

3. **触达人数必须对得上**
   `collegeUsers` 各学院账号数合计 = 466 = `pointOverview.totalUsers`。
   脚本里有一条断言在守这个和，防止哪天改了某个学院的人数忘了改总数。

4. **待审 id 不能与素材 id 撞车**
   通过后素材会 unshift 进 `materials`，id 相同就会出现两条同 id 素材。
   `check-mock-consistency.cjs` 有断言。

## 七、布局与样式的两个坑（2026-11-03 实测）

### ① 页面 wxss 用 `@import` 引入页面目录外的样式表会静默失效

第一版把后台样式放在 `miniapp/styles/admin.wxss`，5 个页面各写一行
`@import "../../styles/admin.wxss";`。结果是**样式整体没生效**：
工作台的 4 个指标卡渲染成竖排的纯文本块（既没有卡片底色，也没有 46rpx 的数字），
而**编译不报任何错误**，`cli preview` 正常出包。

已改为把样式并入 `app.wxss` 末尾（本项目共享样式本来就都在这里）。
`validate-miniapp.cjs` 的 [7] 新增一条检查：页面 wxss 里出现
`@import "…/…"` 直接判错，并注明原因。

### ② 两列网格不用 `calc()` 混用 `%` 与 `rpx`

现在写成：

```css
.a-kpis { display: flex; flex-wrap: wrap; justify-content: space-between; }
.a-kpi  { width: 48.5%; margin-bottom: 18rpx; }
```

`48.5% × 2 = 97%`，剩下的 3% 由 `space-between` 平分，左右间隙自动均匀。
不依赖 `calc()`，也不依赖 flex 的 `gap`（老 WebView 不支持 gap）。
并列按钮的间距用相邻选择器 `.a-acts .a-btn + .a-btn { margin-left: 14rpx; }`。

> 说明：`calc(50% - 10rpx)` 在项目里并非完全不可用 —— 首页「最新素材」的
> `.mini-card` 就是这种写法且显示正常。这里换掉是为了少一层依赖，
> 不是因为它在所有环境都必然失败。

### ③ 怎么验证布局而不用模拟器

模拟器面板在这台机器上不稳定（被挤成窄条）。改用「rpx→px 换算后在 Chrome 里渲染同一份规则」：

```bash
node audit/phase2/work/verify-kpi-layout.cjs
# 输出 D://edge-shot-out//kpi-layout.png，可肉眼确认是否 2 个一行、间隙是否均匀

node audit/phase2/work/verify-scope-layout.cjs
# 输出 D://edge-shot-out//scope-layout.png，左右两个面板分别是「范围选择器」收起态与展开态
```

这验证的是 CSS 几何，不验证 WXSS 编译 —— 两者是不同环节，别混为一谈。

## 八、未做与已知边界

- **无真实鉴权**：原型模式下 `role` 来自本地 mock，任何人都能改本地存储改出自己的角色。
  接真实接口后角色必须由服务端下发，前端只做展示层隐藏（真正的拦截在 API）。
- **写库只在内存**：审核通过、角色变更只改内存中的 mock 数组，**冷启动会还原**；
  下架与精选写的是本地存储，会保留。
- **没有操作留痕**：真实系统里审核、改角色都要进审计日志。小程序端暂未做，
  Web 后台有 audit 模块可查。
- **没有批量上传/导入**：成员管理不支持 Excel 导入，招新不支持批量审核。
- **活动/任务的「编辑」不做草稿版本历史**：保存即生效，没有「先改到草稿再发布」这条路径。
  真实系统应走「已发布内容另存为新版本 → 审核 → 替换」，这里简化为直接覆盖。
- **报名/领取数据是快照**：活动卡上的「报名 86/150」来自 mock，不会因为 C 端真实报名而变动
  （C 端报名状态存在本地 Storage，与这个数字不联动）。
