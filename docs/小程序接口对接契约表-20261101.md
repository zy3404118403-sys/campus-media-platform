## 1. 全局约定（所有接口通用）

| 项 | 约定 |
|---|---|
| 成功结构 | `{ ok: true, data: ... }` |
| 失败结构 | `{ ok: false, message: "中文原因" }` |
| 列表分页 | `{ ok, data: [...], total, page, limit }`（**分页字段在顶层**，不在 data 里） |
| 未登录 | HTTP **401** + `{"ok":false,"message":"请先登录"}` |
| 接口不存在 | HTTP **404** + `{"ok":false,"message":"接口不存在"}` |
| 时间格式 | `"2026-11-30 23:59"` / `"2026-08-16 22:14:16"`（**字符串，非时间戳**） |
| 文件大小 | `file_size` 单位是 **字节**（如 `2165126` ≈ 2.1 MB） |
| 鉴权 | `Authorization: Bearer <token>`；Web 端仍是 Cookie + CSRF，两套并存 |

> ⚠️ **`utils/request.js` 目前只认 `body.data`**。真实接口返回 `{ok, data}`，与现有约定一致，**这一层不用改**。

## 2. 🔴 三个阻断级差异（不改就跑不起来）

### 2.1 论坛列表接口不存在

| 我原来以为 | 实测 |
|---|---|
| `GET /api/forum/threads?board=1` | **HTTP 404 接口不存在** |
| — | ✅ 正确写法：`GET /api/forum/boards/:id/threads` |

```bash
curl -s -H "Authorization: Bearer $T" "http://your-domain.example/api/forum/boards/1/threads"
```

**影响**：`pages/community` 的论坛 tab 必须改成「先取板块 → 再按板块拉帖子」，
而**板块筛选不能只在本地过滤**（现在 mock 是本地 filter，真实接口要逐板块请求）。

### 2.2 博客正文是 HTML，不是段落数组

```json
{ "ok": true, "data": { "id": 1, "title": "...", "content": "<p>作为校园融媒体中心的一员…</p><p>首先，技术选型方面…</p>" } }
```

**影响**：`pages/post-detail` 现在按 `body[]` 逐段渲染，接真实接口后**必须换成 `<rich-text nodes="{{content}}">`**，
并且要处理富文本里的图片宽度溢出（`rich-text` 里的 `img` 默认不设限宽）。

### 2.3 活动详情与任务详情缺关键字段

活动 `GET /api/activities` 的实际字段：

```
id, title, description, date, status, icon, color, poster,
capacity, location, reg_deadline, registered_count, my_status
```

**没有** `organizer / points / intro / agenda / notes` —— 而活动详情页有「主办 / 可得贡献值 / 活动介绍 / 流程安排 / 参与须知」五块。

任务 `GET /api/tasks` 的实际字段：

```
id, title, description, category, points, slots, deadline, status,
created_by, created_by_name, created_at, is_demo, active_claims, done_claims, my_claim
```

**没有** `deliver / requirements` —— 而任务详情页有「交付物」「要求」两块。

→ **这两块要么砍掉，要么请后端加字段**（见第 6 节）。

## 6. 建议的接线顺序

不要一次全接，按「能验证一段就停」的节奏：

```
① utils/format.js + request.js 填 baseURL          ← 只改工具层，页面不动
② 素材库 + 详情（摸清缩略图与 HLS 两件事）           ← 一个页面通，验证整条链路
③ 活动 + 任务（字段映射为主，改动小）                 ← 顺带确认「缺字段」的决策
④ 我的 + 我的列表（依赖 /api/me/stats）              ← 登录态相关一次做完
⑤ 社区 + 帖子详情（结构改造，放最后）                 ← rich-text 与按板块请求
⑥ 消息 + 通知（字段待确认，等后端答复）
```

每一步做完都可以「关掉 mock 开关」真机点一遍，出问题能立刻定位到是哪一层。
