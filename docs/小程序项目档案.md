### 本地工具模块

|---|---|---|
| `utils/mock.js` | 假数据 + 模拟延迟 + `byId` 查找 | 生效中 |

### 待接入的服务端接口（原型阶段仅约定，未实现）

| 原型位置 | 对应平台接口 | 鉴权 | 备注 |
|---|---|---|---|
| 素材列表 | `GET /api/materials` | public | 支持 type/keyword/sort/limit/offset |
| 素材详情 | `GET /api/materials/:id` | public | — |
| 相关推荐 | `GET /api/materials/:id/related` | public | 多因子打分（同活动+35 / 同学院+30 / 同标签+10×3 / 同月+25 / 同类型+12） |
| 下载留痕 | `POST /api/materials/:id/download-agree` | public | 记录 terms_version + 素材/用户快照 |
| 点赞 / 收藏 | `POST /api/materials/like` · `/favorite` | user | — |
| 任务列表 / 领取 / 提交 | `GET /api/tasks` · `POST /api/tasks/:id/claim` · `/:id/submit` | user | 平台侧为旧 if 链实现 |
| 活动报名 | `POST /api/activities/join` · `/cancel` | user | — |
| 登录 | `POST /api/login` | 免 CSRF | 需后端补 Bearer 通道 |

> ✅ **接入前置已就绪（2026-11-01）**：平台已上线 `Authorization: Bearer` 通道 + 会话按端隔离（同端单会话、跨端不互踢），并实测 7 项全过。小程序侧只需：登录请求带 `X-Client: miniapp` 拿 body token，后续请求带 `Authorization: Bearer <token>`，写接口无需 CSRF。详见《后端Bearer与会话隔离-改动报告-20261101.md》。

## 八点五、本轮设计决策（供后续对齐，改这些之前先想清楚）

| 决策 | 理由 | 代价 |
|---|---|---|
| **「我的收藏 / 下载 / 投稿」合成一页 `my-list`** | 三者结构一致（缩略图+标题+元信息+时间），差异只在标题、空态与投稿的状态筛选 | 单页要处理三种模式分支；换来改样式只改一处 |
| **统计数字由 mock 列表派生** | 避免「120 贡献值但投稿 0」这类语义矛盾 | 接真实接口后要改为读服务端 `stats` |
| **活动报名不做二次确认** | 报名可随时取消，是低风险可逆操作；弹窗只增加摩擦 | 缺少一次「反悔」机会，用「取消报名」兜底 |
| **取消报名 / 退出登录保留确认** | 有实际后果（名额释放、需要重新登录） | — |
| **任务领取移到详情页** | 领取前必须看到交付物与要求，否则用户不知道要交什么就占掉名额 | 列表页多一次点击 |
| **提交成果用页内表单而非弹窗** | 需要写说明 + 贴链接，弹窗空间不够，键盘会遮挡 | 表单展开时底栏切为「取消 / 提交」 |
| **空提交前置拦截并给出具体原因** | 「不少于 10 个字」比「请填写内容」可执行 | — |
| **多行字段改上下结构左对齐** | 长文本右对齐读起来费劲（首版踩到，已改） | — |
| **投稿退回原因直接展示在列表** | 被退回时最关心的是「为什么」，不该再多点一层 | 列表卡片高度增加 |
| **分享按钮用「透明按钮覆盖」而非直接给 button 设宽** | 实测 `<button>` 默认宽度会覆盖 `width: 96rpx`（量到 184px），改用绝对定位铺满 | 多一层 view 包装 |
| **社区三 tab 合成一页 `community`** | 博客/论坛/表白墙都是「帖子流」，差异只在卡片形态；拆成三个 tab 页会超 tabBar 上限（已占满 5 个） | 单页三分支；论坛板块筛选要在 JS 里算好 `shownThreads`（WXML 不能过滤） |
| **帖子详情合成一页 `post-detail`** | 三者排版一致（作者/时间/正文/评论），差异只有「有没有标题」「有没有封面」 | 用 `?type=` 分支 |
| **社区入口放首页小节而非 tabBar** | tabBar 5 个位置已满，塞第 6 个会导致图标变小、文字挤 | 首页「校园社区」区块 + 「进入社区 →」 |
| **表白墙发帖用页内面板而非新页面** | 只需一段文字，开新页反而多一次跳转 | 面板展开时按钮变「收起」 |
| **`post-wrap` 用 padding-top 而非给首元素 margin** | 父容器无上内边距时，首个子元素的 `margin-top` 会**折叠出去**，标题会贴住导航栏（实测 h1 top 与 page top 都是 15px） | 多一层包裹 |
| **上传页切类型时清空已选文件** | 图片选完再切到视频，文件类型不合法；留到提交才发现体验更差 | 用户要重新选一次（已用提示文案说明上限同步变化） |
| **上传后写进 `mock.myUploads` 并跳「我的投稿」** | 让投稿闭环在原型阶段就能走通；否则提交完看不到结果 | 接真实接口后改为服务端返回并刷新列表 |
| **上传入口放三处：我的页菜单 / 我的投稿页 CTA / 空态按钮** | 投稿是低频动作，入口太深就没人用；空态是「想投稿的人最需要引导」的时刻 | 三处文案保持一致 |
| **系统通知与私信合并一页** | 用户心智里都是「有人找我」；分两个入口会让「去哪看」变成一道选择题 | 通知固定置顶，私信在下方 |
| **通知只分「全部/未读」，不按类型分 tab** | 通知量不大，按类型分会让人在四个 tab 间找「刚提醒我的那条」 | 类型靠图标颜色区分 |
| **「全部已读」后自动从「未读」切回「全部」** | 否则列表立刻变空，用户会以为「通知没了」 | 少一个「再点一下切回来」的动作 |
| **聊天用 `scroll-into-view` 而不是 `pageScrollTo`** | 键盘弹起时 `pageScrollTo` 的位置算不准；`scroll-into-view` 绑定最后一条消息的 id 更稳 | 需要给每条消息生成稳定 id |
| **发送消息先上屏再落库** | 输入框要立刻清空，用户不该等网络 | 真实接口失败时需补「发送失败可重试」状态（尚未做） |
| **发帖统一到 `post-create` 一页** | 三种类型共用「写正文 + 提交」，差异只有标题/板块/匿名；原本表白墙在社区页内联发帖，等于两套校验与发布逻辑要同步维护 | 表白墙发帖多一次跳转（原来原地发） |
| **发布后直接 `redirectTo` 到该条详情** | 用户最想看的是「我发出去长什么样」，回列表还要自己找 | 返回键会回到社区（`redirectTo` 替换了发布页，栈不增长） |
| **社区页加 `onShow` 重读 mock** | 否则从发布页返回时列表仍是旧的，新内容看不见 | 每次返回都重置列表滚动位置；点赞态用 id 映射保留 |
| **下载规范用自绘弹窗，不用 `wx.showModal`** | 原生弹窗**放不了勾选框**，且**无法截图/自动化验证**；「勾选后才可下载」是这条合规约束的关键 | 多约 60 行 WXML/WXSS；遮罩需 `catchtouchmove` 防穿透滚动 |
| **列表页用「代际编号」作废在途回调** | 分页有 240–260ms 延迟，与下拉刷新/筛选重置交叉时会跳页或让 `shown` 与真实卡片数不一致。重置时 `_gen++`，延迟回调先比对 `gen` 再执行 | 每个列表页多 3–4 行；接真实接口后这套机制仍然需要（网络延迟只会更长） |
| **异步回调前检查页面是否还在** | 上传/发布/报名/领取都有 360–520ms 延迟，用户可以中途退出。`onUnload` 里置 `_alive=false`，回调先判再 `setData` | 上传页还要在 `onUnload` 里 `clearInterval` 与 `clearTimeout`，否则退出后仍会被强跳 |
| **底部留白按「栏高 + 安全区」计算，不写死** | 写死 `200rpx` 在有安全区的设备上刚好、在安卓上多出约 37px 空白。改为 `calc(160rpx + env(safe-area-inset-bottom))` 后两端观感一致 | 栏高变化（加按钮/改内边距）时要同步改这两个值 |
| **交互元素叠 px 下限 `max(88rpx, 44px)`** | rpx 随屏幕宽度等比缩放：375 宽时 `88rpx` 正好 44px，但 328 宽的窄屏上只有 38.5px，**低于 44px 无障碍下限**（vivo 真机实测 4 项全部偏小）。叠一条 px 下限后宽屏仍等比、窄屏不低于 44px | 窄屏上按钮比同屏其他元素略大一点；`max()` 不支持时上一行 rpx 值仍生效 |
| **真机上「视口高度」不能用 `windowHeight` 判断** | 实测 iPad 报 723.95 而 CSS 真实视口约 1084（差 360）；Android 差 90。`windowHeight`、`screenHeight`、`safeArea` 三套坐标系真机上不一定自洽 | 要判断 fixed 元素是否贴底，必须用 `selectViewport().boundingClientRect()` + `scrollOffset()` 校正，不能拿 `windowHeight` 硬算 |
