## 一、导航结构调整（本轮拍板）

**原结构**：tabBar = 素材 · 专题 · 活动 · 任务 · 我的（首屏直接是素材瀑布流）

**问题**：进来就是列表页，没有门户感；专题占了一个 tab 却内容极少（仅 3 个专题集 + 4 篇文章）。

**新结构**：

```
tabBar： 首页 · 素材 · 活动 · 任务 · 我的
                ↓
         专题降为二级页（首页入口进入）
```

| tab | 页面 | 定位 |
|---|---|---|
| 首页 | `pages/home/home`（**新建**） | 门户：品牌 + 快捷入口 + 精选 + 最新 + 动态 |
| 素材 | `pages/index/index` | 全量检索与筛选（保留现有能力） |
| 活动 | `pages/activities/activities` | 活动列表 |
| 任务 | `pages/tasks/tasks` | 任务大厅 |
| 我的 | `pages/profile/profile` | 个人中心 |

## 二、首页信息架构（7 个区块）

| # | 区块 | 内容 | 数据来源 |
|---|---|---|---|
| 1 | 品牌头 | 融媒体中心 + 一句话定位 + 搜索入口（点击进搜索页） | 静态 |
| 2 | 数据栏 | 素材 N · 专题 N · 本周新增 N | `GET /api/materials` 总数 / `/api/collections` |
| 3 | 快捷入口 | 素材库 / 专题 / 活动 / 任务 / 排行榜 / 关于（6 宫格） | 静态路由 |
| 4 | 精选 | `featured` 素材横向大卡（封面 + 标题 + 播放/图片标识） | `GET /api/materials?featured=1` |
| 5 | 最新素材 | 2×2 网格 + 「查看全部 →」 | `GET /api/materials?limit=4` |
| 6 | 进行中活动 | 最多 2 条，带"剩余名额" | `GET /api/activities` |
| 7 | 任务提醒 | 最多 2 条，带截止倒计时 | `GET /api/tasks` |
| 8 | 专题集 | 横向滑动卡片 | `GET /api/collections` |

> 首页只做「导流 + 精选」，不重复素材库的筛选能力——避免两页功能重叠。

## 四、比页面更该先做的 4 件事

| 项 | 现状 | 何时做 |
|---|---|---|
| **抽自定义组件** | 空态/骨架/加载更多全在 `app.wxss`，靠 class 复用 | 页面到 12 个前必须抽（`empty-state` `skeleton` `load-more` `image-viewer` `rich-text` `search-bar`） |
| **分包** | 当前全在主包 | 页面 > 15 个时拆：主包留 5 tab + 登录，其余按域分包 |
| **富文本渲染** | 文章正文是手写段落 | 接真实文章前需 `rich-text` + 节点白名单过滤 |
| **微信分享** | 未做 | 分享卡片是拉新主路径，需 `onShareAppMessage` + 落地页 |
